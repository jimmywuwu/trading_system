## Operating stance

We will finish the roadmap in priority order, but each milestone is a gated research package, not a sprint to manufacture alpha. Negative evidence is a valid deliverable. If a milestone fails robustness or data-quality checks, we document the failure and move on instead of tuning until the backtest confesses.

## Workload rhythm

### Default cadence

- **One active milestone at a time.** No jumping ahead unless the next milestone only needs prerequisite discovery.
- **Small batches:** 1 research package per cycle, with explicit validation and documentation before the next package starts.
- **Stop-loss on rabbit holes:** if a sub-study cannot produce interpretable evidence after the defined data/validation pass, mark the blocker and either ask for help or downgrade the milestone.
- **Chat updates:** concise gate/status update only; long reasoning goes to repo/Notion draft.

### Per-milestone package shape

Each milestone must produce:

1. **Research/design note**
   - mechanism
   - falsifiable question
   - expected evidence
   - controls / benchmarks
   - failure modes
2. **Data-quality evidence**
   - fixture/source identity
   - timestamp semantics
   - row/bucket coverage
   - gap checks
   - stale/late/revision risks
3. **Executable study or feasibility probe**
   - script path
   - input path(s)
   - deterministic command
   - output JSON/Markdown path(s)
4. **Validation log**
   - exact commands run
   - test/smoke result
   - known limitations
5. **Decision record**
   - Reject / Research Only / Risk Filter Candidate / Paper Candidate
   - rationale
   - next owner or next milestone

## Gate policy

A milestone is complete only when all three are true:

- **Evidence exists:** raw outputs or reports are committed in `reports/`, `artifacts/`, `spikes/`, or a Notion draft.
- **Verification exists:** commands/tests are recorded and have actually been run.
- **Decision exists:** conclusion grade is explicit and conservative.

Trader handoff is forbidden unless the evidence is at least `Paper Candidate`. Current prior: most roadmap milestones should end as `Research Only` or `Risk Filter Candidate`.
